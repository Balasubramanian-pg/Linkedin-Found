# Managed Tables vs External Tables in Unity Catalog

## Question
What is the difference between **Managed Tables** and **External Tables** in Databricks Unity Catalog, and how do their storage lifecycles differ?


## 1. Comparison Matrix

| Feature | Managed Table | External Table |
| :--- | :--- | :--- |
| **Storage Location** | Managed automatically in the schema/catalog default storage path. | Explicitly defined custom storage path (`LOCATION 'abfss://...'`). |
| **`DROP TABLE` Behavior**| **Permanently deletes metadata AND underlying data files**. | Deletes metadata catalog pointer **ONLY**; physical data files remain intact. |
| **File Management** | Unity Catalog manages vacuuming, compaction, and lifecycle. | User/admin manages underlying cloud storage directory. |
| **Performance** | Supports all performance features (Predictive Optimization, Liquid Clustering). | Fully supported in Delta format. |
| **Best Used For** | Curated internal Gold/Silver analytical tables. | Integrating with existing external data lakes / legacy S3/ADLS buckets. |


## 2. SQL Syntax

```sql
-- 1. Managed Table (No LOCATION specified)
CREATE TABLE prod_catalog.finance.dim_customers (
    customer_id STRING,
    name STRING
);

-- 2. External Table (Explicit LOCATION specified)
CREATE TABLE prod_catalog.finance.fact_external_trades (
    trade_id STRING,
    amount DOUBLE
)
LOCATION 'abfss://curated@datalake.dfs.core.windows.net/external_trades/';
```
