# Scenario 05: Delta MERGE Implementation for Inserts and Updates (SCD Type 1 & 2)

## Problem Statement
A target Delta table stores customer master data. Incoming daily batches contain a mix of newly registered customers (inserts), profile updates (updates), and soft deletions. How do you implement this efficiently using Delta Lake `MERGE INTO`?


## 1. Pattern 1: SCD Type 1 Upsert (Overwrite In-Place)

When historical attribute changes do not need versioning:

```sql
MERGE INTO silver_dim_customers AS target
USING (
    -- Deduplicate source batch to ensure 1 distinct row per customer_id
    SELECT * FROM incoming_customer_staging
    QUALIFY ROW_NUMBER() OVER (
        PARTITION BY customer_id 
        ORDER BY last_updated_ts DESC
    ) = 1
) AS source
ON target.customer_id = source.customer_id
-- Handle soft deletes
WHEN MATCHED AND source.is_deleted = TRUE THEN
  UPDATE SET 
    target.status = 'INACTIVE',
    target.is_deleted = TRUE,
    target.updated_at = current_timestamp()
-- Handle updates
WHEN MATCHED AND source.last_updated_ts > target.last_updated_ts THEN
  UPDATE SET 
    target.first_name = source.first_name,
    target.last_name = source.last_name,
    target.email = source.email,
    target.phone_number = source.phone_number,
    target.address = source.address,
    target.last_updated_ts = source.last_updated_ts,
    target.updated_at = current_timestamp()
-- Handle new customer inserts
WHEN NOT MATCHED AND source.is_deleted = FALSE THEN
  INSERT (
    customer_id, first_name, last_name, email, 
    phone_number, address, status, is_deleted, 
    last_updated_ts, created_at, updated_at
  )
  VALUES (
    source.customer_id, source.first_name, source.last_name, source.email,
    source.phone_number, source.address, 'ACTIVE', FALSE,
    source.last_updated_ts, current_timestamp(), current_timestamp()
  );
```


## 2. Pattern 2: Python / DeltaTable API Implementation

Using the programmatic PySpark DeltaTable API:

```python
from delta.tables import DeltaTable
from pyspark.sql import functions as F

target_table = DeltaTable.forName(spark, "silver_dim_customers")

# Prepare source microbatch with deduplication
source_df = (
    spark.read.table("stg_customer_updates")
    .withColumn("rn", F.row_number().over(
        Window.partitionBy("customer_id").orderBy(F.col("last_updated_ts").desc())
    ))
    .filter(F.col("rn") == 1)
    .drop("rn")
)

(
    target_table.alias("t")
    .merge(
        source_df.alias("s"),
        "t.customer_id = s.customer_id"
    )
    .whenMatchedUpdate(
        condition="s.last_updated_ts > t.last_updated_ts",
        set={
            "first_name": "s.first_name",
            "last_name": "s.last_name",
            "email": "s.email",
            "address": "s.address",
            "last_updated_ts": "s.last_updated_ts",
            "updated_at": "current_timestamp()"
        }
    )
    .whenNotMatchedInsert(
        values={
            "customer_id": "s.customer_id",
            "first_name": "s.first_name",
            "last_name": "s.last_name",
            "email": "s.email",
            "address": "s.address",
            "status": F.lit("ACTIVE"),
            "is_deleted": F.lit(False),
            "last_updated_ts": "s.last_updated_ts",
            "created_at": "current_timestamp()",
            "updated_at": "current_timestamp()"
        }
    )
    .execute()
)
```


## 3. Merge Performance Optimization Rules

1. **Partition Pruning in the Join Condition:**
   - If target is partitioned by `region`, always add `AND target.region = source.region` in the `ON` clause to limit the scan to only affected partitions.
2. **Compact Target Files Prior to Heavy Merges:**
   - Ensure target table does not have millions of tiny files (`OPTIMIZE` before running massive merge jobs).
3. **Pre-Filter Staged Updates:**
   - Filter out rows in the source where attributes did not actually change.
