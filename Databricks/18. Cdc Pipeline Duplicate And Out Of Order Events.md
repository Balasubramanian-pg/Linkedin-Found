# Handling Duplicate & Out-of-Order Events in a CDC Pipeline

## Question
Your Change Data Capture (CDC) pipeline ingests database event streams from Kafka. Due to network retries, the pipeline receives duplicate and out-of-order change events. How do you ensure the target Delta table reflects the exact true current state?


## 1. Solution: Microbatch Ranking with Sequence Numbers

Every CDC record from Debezium / Oracle GoldenGate contains a source transaction timestamp (`_source_ts`) or monotonic Log Sequence Number (`_lsn`).

```python
from pyspark.sql import functions as F
from pyspark.sql.window import Window

def process_cdc_microbatch(microbatch_df, batch_id):
    # Step 1: Deduplicate within the incoming microbatch, selecting highest LSN / latest timestamp
    window_spec = Window.partitionBy("primary_key").orderBy(
        F.col("_source_lsn").desc(),
        F.col("_source_ts").desc()
    )
    
    clean_cdc_batch = (
        microbatch_df
        .withColumn("rn", F.row_number().over(window_spec))
        .filter(F.col("rn") == 1)
        .drop("rn")
    )
    
    clean_cdc_batch.createOrReplaceTempView("staged_cdc")
    
    # Step 2: Merge into target ensuring older out-of-order events never overwrite newer data
    spark.sql('''
        MERGE INTO silver_target_table AS target
        USING staged_cdc AS source
        ON target.primary_key = source.primary_key
        WHEN MATCHED AND source._op = 'D' AND source._source_lsn >= target._source_lsn THEN
          DELETE
        WHEN MATCHED AND source._source_lsn >= target._source_lsn THEN
          UPDATE SET *
        WHEN NOT MATCHED AND source._op <> 'D' THEN
          INSERT *
    ''')
```
